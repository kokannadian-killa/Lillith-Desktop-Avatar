# Lillith on Android

Lillith floats over your other apps, plays the same clips as on the desktop,
reacts to taps, falls to the bottom of the screen when you drop her, and can
chat using a model that runs **entirely on your phone**.

Everything Android-specific lives in this `android/` folder:

| Path | What it is |
|---|---|
| `app/AndroidManifest.xml` | Package `com.kokannadian.lillith`, minSdk 26 (Android 8), targetSdk 34 |
| `app/src/…/SetupActivity.java` | First-run setup: overlay permission, notification, pick a GGUF model, size, launcher icon, start/hide |
| `app/src/…/IconSet.java`, the `ICON-ALIASES` block of `AndroidManifest.xml` | One `activity-alias` per icon (generated by `branding/make-icons.py`); the picker enables one, disables the rest |
| `app/src/…/OverlayService.java` | Foreground service that draws her in a `TYPE_APPLICATION_OVERLAY` window, forwards touches, shows her speech bubble |
| `app/src/…/ChatActivity.java`, `LocalLlm.java` | Chat with Lily via on-device llama.cpp |
| `app/src/…/MenuActivity.java` | Long-press menu (chat, kiss, wave, dance, settings, hide) |
| `rust/` (`lillith-android` crate) | The desktop brain (`lillith-core`), animator and clips (`lillith-anim`) driven over JNI; gravity, drag, tap/long-press, LRU page cache. The JNI glue is behind `cfg(target_os = "android")`; the rest builds and is tested on Linux as part of the workspace |
| `llm/` | `liblillith_llm.so`: a ~200-line C JNI shim over llama.cpp (pinned tag `b11829`), CPU-only |
| `app/src/…/ClipPack.java`, `clip-pack.py` | The clip pack: clips that don't fit in an uploadable (<1 GB) APK ship as one zip on the same release; setup downloads it once (token-gated, resumable, SHA-256-checked) |
| `build-apk.sh` | One-shot build of the debug APK (no Gradle needed); bundles the voice models from the voice kit |

## Install (Ko)

1. Copy `lillith-debug-arm64.apk` to the phone (or `adb install -r lillith-debug-arm64.apk`).
   Opening the file on the phone asks to allow installs from that app (Files/Chrome): allow it once.
   It's a debug build signed with a debug key, so Play Protect may warn: choose **Install anyway**.
2. Open **Lillith**. The setup screen walks you through:
   1. **Float over other apps**: tap the button, find Lillith, turn on *Allow display over other apps*, come back.
   2. **Notification** (Android 13+): allow it. Android requires a small "Lillith is on screen" notification
      while she's out. It also has **Chat** and **Hide** buttons.
   3. **Local chat model (optional)**: first copy a `.gguf` file onto the phone yourself (USB, file manager).
      Tap **Pick GGUF file…** and choose it. It's copied into Lillith's private storage, which needs free space
      equal to the file size. A 1–4B model at Q4_K_M (0.7–2.5 GB) suits most phones; 7–8B needs 8 GB+ RAM.
      You can skip this: she still plays, she just can't chat.
   4. **Size**: 100% = the desktop default (0.55 × the 400 px clips, in dp, so the same apparent size).
   5. **Icon**: tap one of the 15 launcher icons (default *Phantomcore Red*). The home screen may reload
      for a moment while the launcher picks it up; some launchers only update after a restart of the launcher.
   6. **The rest of her clips (once)**: only shown when the APK was built with a clip pack
      (`LILLITH_CLIP_PACK_MB`). Paste a GitHub token that can read the repo (the repo is private) and tap
      **Download the rest of her clips**. It downloads one zip from the same release, resumes after a dropped
      connection, retries, checks the zip's and every file's SHA-256 and unpacks it. The token is held in
      memory for that download only, never saved. No token? Download the pack zip from the release page in the
      phone's browser and tap **Or pick … you downloaded**: same checks, no network use by the app. She plays without those clips meanwhile, and restarts with
      them when it finishes.
   7. **Start Lillith**. The first start unpacks her clips (~450 MB) and her voice models (~400 MB), checking
      each voice file's SHA-256; it needs about 0.9 GB free and takes a little while. If a voice file is missing
      or corrupt, setup says which one and stops.
3. Using her:
   - **Tap** her: the same reactions as a desktop click (double tap etc. go through the same brain).
   - **Hold** (½ s): the menu.
   - **Drag** her anywhere. **Let go** and she falls to the bottom of the screen with a soft bounce.
   - She idles, cycles flirty poses, wanders along the bottom, and falls asleep when left alone, like on desktop.
   - **Hide**: notification → *Hide*, or menu → *Hide Lillith*. Settings: open the app again.

Arm64 phones only (nearly every phone from 2017 on). Android 8.0+.

## Privacy: fully local

- An APK with every clip inside (`LILLITH_CLIP_PACK_MB=0`, the default) has **no `INTERNET` permission**,
  so Android blocks every socket the app could open, loopback included. Check with
  `aapt2 dump permissions lillith-debug-arm64.apk`.
- A clip-pack APK (the published ones, because 232 clips + voice are ~1.8 GB and an upload must stay under
  ~1 GB) has `INTERNET` for exactly one thing: the clip-pack download you start in setup
  (`ClipPack.java`: HTTPS to `api.github.com`, then GitHub's signed release-asset link, without the token).
  Chat, voice and everything else never open a socket.
- The chat model is llama.cpp **inside the app process** (JNI). There is no server, not even on loopback,
  which is why INTERNET isn't needed.
- No model downloads, no telemetry, no analytics, no update checks. The only model is the GGUF you pick.
- `allowBackup="false"`: chats and the model aren't sent to Google backup.

## Build it yourself

Needs Linux x86_64 and about 4 GB for the toolchain:

```bash
# Rust target (rustup toolchain 1.85.1, same as the desktop gate)
rustup target add aarch64-linux-android
# Android SDK command-line tools + JDK 17, then:
sdkmanager "platforms;android-34" "build-tools;34.0.0" "ndk;27.2.12479018" "cmake;3.22.1"

export ANDROID_HOME=/path/to/sdk JAVA_HOME=/path/to/jdk-17
export CARGO_TARGET_DIR=/path/to/target-android      # optional
export LLAMA_CPP_DIR=/path/to/llama.cpp              # optional; else cloned at tag b11829 at build time
# Voice models: unpack the release voice kit once (models never go in git)
tar -xJf lillith-voice-kit-<sha>.tar.xz -C /path/to/kit
export LILLITH_VOICE_MODELS=/path/to/kit/tools/lillith-voice/models
android/build-apk.sh
# -> $CARGO_TARGET_DIR/apk/lillith-debug-arm64.apk
```

What the script does: `cargo build --release --target aarch64-linux-android -p lillith-android` →
CMake/NDK builds the llama.cpp shim → copies `assets/generated/manifest.toml` + every `*_sheet.png`
(art and manifest unchanged) → stages the voice models into `assets/voice/` → `javac` + `d8` → `aapt2 link` → `zipalign` → `apksigner` with a generated
debug key (`$OUT/debug.keystore`, not committed). The only network access is the optional one-time
llama.cpp source clone, at build time.

### Voice models in the APK

`build-apk.sh` checks the kit's `models/SHA256SUMS` before building, then uses
`tools/lillith-voice/android/link_assets.sh` to put the models under `assets/voice/` (hard links in the
stage dir, so no extra disk), writes `assets/voice/SHA256SUMS` + `voice.properties`, and stores `.onnx`,
`.bin`, `.npy` and `.model` **uncompressed** (`aapt2 -0`). On first run `AssetInstaller` copies every
listed file to `filesDir/voice/` and checks its SHA-256; a missing or corrupt file fails setup with its name.
The build fails if the models aren't found (set `LILLITH_VOICE_MODELS`); `LILLITH_VOICE=0` builds without voice.

| env | default | what |
|---|---|---|
| `LILLITH_VOICE_FLAVOR` | `quality` | fp32 `flow_lm_main` (recommended by `ANDROID_ASSETS.md`); `small` = int8 (experimental: can cut lines short) |
| `LILLITH_VOICE_STT` | `0` | `1` also packs whisper tiny.en int8 + silero VAD for the mic. Off by default: the app is speaking-only (no mic permission, no STT runtime) |
| `LILLITH_VOICE_KOKORO` | `0` | also ship the Kokoro p1 fallback (+353 MB). Off by default: Android has no Kokoro runtime or espeak-ng G2P yet, so the planned fallback is Android `TextToSpeech` |
| `STAGE_ONLY=1` | | stage clips + voice into `$OUT/stage/assets`, list them, stop (no SDK/NDK/cargo needed) |

`assets/voice/` (quality, default, speaking only): `pocket/{text_conditioner,flow_lm_main,flow_lm_flow,mimi_decoder}.onnx`,
`pocket/{tokenizer.model,bundle.json,bos_before_voice.npy,voices/lillith.npy}`: 8 files, 382 MiB.
With `LILLITH_VOICE_STT=1` add `stt/{silero_vad,tiny.en-encoder.int8,tiny.en-decoder.int8}.onnx`,
`stt/tiny.en-tokens.txt`: 12 files, 481 MiB.

Size: the APK is about **0.85–0.9 GB** (clips 447 MiB + voice 382 MiB + native libs; +25–40 MB once the ONNX
Runtime libs are added; about 0.1 GB more with `LILLITH_VOICE_STT=1`), and the phone needs about the same again for the unpacked copy. Fine for sideloading
(well under the 4 GB zip limit). Google Play would need Play Asset Delivery (150 MB base limit).

The Linux gate is unaffected: `lillith-android` is a workspace member whose JNI module only compiles for
Android, so `cargo fmt --check`, `build --locked`, `test --locked` and `clippy -D warnings` cover its engine
and tests on Linux.

## Known limits

- The overlay window is a rectangle around her. Touches on transparent pixels inside it are ignored, but
  Android doesn't pass them through to the app underneath.
- No window perching (Android has no window list for other apps); she lands on the bottom of the screen.
- No sound or voice yet: the voice **models** ship in the APK and are unpacked and verified, but there is no
  Android voice runtime yet (ONNX Runtime / sherpa-onnx libs, the Pocket TTS port, `AudioTrack`/`AudioRecord`,
  `RECORD_AUDIO`). `AssetInstaller.clonedVoiceReady()` / `fallbackVoice()` are there for it, and the log
  (`lillith_voice` tag) says which voice she'd use. Plan for her voice (Ko's clone, in the APK, still no `INTERNET`): see the
  `lillith-voice` kit's `android/INSTALL-android.md` and `android/ANDROID_ASSETS.md` (asset list, sizes,
  SHA-256, ONNX Runtime ABIs, APK size ≈ 530–545 MB for the recommended quality flavour; the int8 small flavour is experimental). Android `TextToSpeech` is the
  fallback. The desktop sensors (CPU, Bluetooth, notifications…) aren't wired on Android.
- Chat replies arrive all at once (no token streaming yet) and appear in her bubble when she's on screen.
